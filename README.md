# 흑과 백 — The Genius 시즌 3 1화 데스매치 규칙 기반 온라인 게임

아이폰 Safari와 갤럭시 Chrome에서 앱 설치 없이 플레이하는 1:1 온라인 웹게임입니다. 정적 웹페이지는 GitHub Pages, 온라인 방/게임 상태는 Supabase를 사용합니다.

## 포함 파일
- `index.html` — 모바일 UI와 온라인 게임 로직
- `supabase.sql` — 기존 Supabase 프로젝트에 새 규칙과 RPC 함수를 적용하는 SQL
- `README.md` — 설정/배포 안내

## 반영한 게임 규칙
- 방 생성 시 흑과 백 1, 흑과 백 2 또는 베팅! 흑과 백을 선택합니다. 초대 링크/방 참가 화면에서는 방장이 정할 옵션(게임 모드, 상대로 지목된 플레이어)을 숨깁니다.
- 흑과 백 1은 각자 0~8 타일을 한 장씩 보유합니다. 0·2·4·6·8은 검은 타일, 1·3·5·7은 흰 타일이며 사용한 타일은 다시 쓸 수 없습니다. 높은 숫자가 라운드 승점을 얻고, 9라운드 후 동점이면 새 타일 9장으로 연장전을 반복합니다. 상대의 남은 타일 수와 미사용 타일의 검정/흰색 현황을 표시하고, 상대가 낸 타일도 숫자는 숨긴 채 색상만 표시합니다.
- 진행 로그와 게임 종료 로그는 최근 라운드부터 내림차순으로 표시합니다.
- 흑과 백 2는 기존 포인트 제시 규칙을 유지합니다.
- **베팅! 흑과 백**은 0~9 숫자 타일의 비공개 순서와 30칩 베팅 계획을 먼저 확정합니다. 숫자 타일은 0·2·4·6·8 검정, 1·3·5·7·9 흰색입니다. 시작 시 각 타일 베팅 입력은 0으로 비어 있으며, 배분 전 남은 칩은 빨간 사각형으로 표시합니다. 확정 전 각 타일에 최소 1칩씩 배분하고 총 30칩을 모두 걸어야 합니다. 두 사람이 계획을 확정하기 전에는 상대 순서와 베팅을 볼 수 없습니다. 대결 중 상대 타일은 숫자를 숨기고 검정/흰색만 표시합니다. 한 순서에 같은 칩을 걸면 숫자를 공개하고, 다르면 적게 건 플레이어가 보유 칩을 먼저 사용해 맞추거나 포기할 수 있습니다. 보유 칩이 부족하면 미진행 타일별로 회수할 칩 수를 직접 정할 수 있으며, 회수량 합계는 부족분과 일치해야 하고 각 타일에는 최소 1칩이 남아야 합니다. 포기한 순서의 숫자는 공개하지 않고 해당 베팅 칩은 상대가 가져갑니다. 열어 승리하면 양쪽 베팅을 가져가고, 숫자가 같으면 각자 베팅을 돌려받습니다. 각 순서의 승리/패배/무승부를 표시하며, 10개 순서 후 보유 칩이 많은 플레이어가 승리합니다.
- 각 플레이어는 본 게임 시작 시 99포인트를 받습니다.
- 총 9라운드이며, 매 라운드 선 플레이어가 먼저 포인트를 제시하고 후 플레이어가 그 제시와 갱신된 잔여 포인트 표시등을 확인한 뒤 제시합니다.
- 제시 가능한 포인트는 0부터 자신의 남은 포인트까지입니다. 제시 즉시 해당 포인트가 차감됩니다.
- 한 자릿수(0–9)는 검은색, 두 자릿수(10 이상)는 흰색 칩으로 표시합니다.
- 잔여 포인트 표시등은 80–99 / 60–79 / 40–59 / 20–39 / 0–19 구간에 따라 5단계부터 1단계까지 표시합니다. 선 플레이어의 포인트가 차감되면 후 플레이어가 제시하기 전에 상대 화면에도 표시등이 갱신됩니다.
- 더 높은 포인트를 제시한 플레이어가 승점 1점을 얻고 다음 라운드 선 플레이어가 됩니다. 동점이면 승점 변화 없이 직전 선 플레이어가 다시 선 플레이어가 됩니다.
- 한 플레이어가 승점 5점을 먼저 얻으면 즉시 종료합니다.
- 9라운드 종료 시 승점이 동점이면 기존 잔여 포인트를 버리고 양쪽 모두 33포인트로 초기화해 3라운드 연장전을 진행합니다. 연장전 종료 후에도 승점이 같으면 무승부로 표시합니다.
- 방 생성 시 '상대로 지목된 플레이어'를 방장/참가자 중에서 지정합니다. 두 명이 입장하면 해당 플레이어가 방장 선공, 참가자 선공 또는 코인 토스를 선택해 1라운드 선 플레이어를 결정합니다.

## 1. Supabase 설정
1. 기존 Supabase 프로젝트의 **SQL Editor**를 엽니다.
2. 이 ZIP의 `supabase.sql` 전체 내용을 붙여 넣어 실행합니다. 기존 `bw_rooms` 테이블이 있다면 필요한 열을 추가하고 RPC 함수들을 교체합니다. 방 테이블 자체를 삭제하지는 않습니다.
3. **Project Settings → API**에서 Project URL과 Publishable key를 확인합니다.
4. `index.html`에서 `SUPABASE_URL`이 내 프로젝트 URL인지 확인합니다. 현재 파일에는 대화 중 사용한 프로젝트 URL이 들어 있습니다.
5. `SUPABASE_ANON_KEY`의 `PASTE_SUPABASE_ANON_KEY_HERE`를 본인의 Publishable key로 바꿉니다. 기존 GitHub 코드에 있던 키를 사용하면 됩니다. `sb_publishable_...` 형식의 키를 사용하고, `sb_secret_...` 또는 `service_role` 키는 브라우저 코드에 절대 넣지 마세요.

> 최신 게임 기능을 적용하려면 전체 `supabase.sql`을 다시 실행하고 새 `index.html`도 배포해야 합니다. 이전 HTML과 새 SQL을 섞어 쓰면 함수 응답/매개변수 오류가 날 수 있습니다.

> 베팅! 흑과 백을 사용하려면 `supabase.sql`을 다시 실행해 새 게임 모드와 베팅 RPC 함수를 적용해야 합니다.

## 2. GitHub Pages 배포
1. ZIP을 풀고 `black_white_online/index.html` 파일을 엽니다.
2. 위의 Publishable key를 설정합니다.
3. GitHub 저장소에서 기존 `index.html`을 이 새 파일로 교체하고 Commit changes 합니다. `supabase.sql`과 `README.md`는 웹 루트에 올릴 필요는 없습니다.
4. GitHub Pages 주소를 열고 `Ctrl + Shift + R`로 강력 새로고침합니다. 휴대폰에서는 페이지를 새로고침하거나 브라우저 탭을 닫고 다시 엽니다.

## 3. 대전 시작
1. 방장이 닉네임과 게임 모드를 선택합니다. 흑과 백 1·2에서는 '상대로 지목된 플레이어'도 선택합니다.
2. 초대 코드/링크를 상대에게 전달합니다.
3. 상대가 입장하면 지정된 플레이어가 선 플레이어를 선택합니다.
4. 선 플레이어가 먼저 포인트를 제시합니다. 제시 즉시 잔여 포인트와 표시등이 바뀝니다.
5. 후 플레이어는 공개된 선 플레이어의 제시와 현재 표시등을 확인하고 포인트를 제시합니다.

베팅! 흑과 백에서는 두 플레이어가 각각 타일 순서와 30칩 배분을 확정한 뒤 10개 순서의 승부를 진행합니다. 서로 다른 베팅이면 칩이 적은 쪽이 보유 칩을 먼저 사용하고, 부족분은 미진행 타일별로 직접 회수량을 정해 매치하거나 언제든 포기할 수 있습니다. 타일마다 최소 1칩은 남겨야 합니다.

## 참고
- 제시 포인트 0은 규칙의 '원하는 만큼'을 0 이상으로 해석해 허용했습니다. 0도 한 자릿수이므로 검은색으로 표시됩니다.
- 코인 토스는 서버에서 무작위로 선 플레이어를 선택합니다.
- 이 프로젝트는 비공식 팬메이드 게임입니다. Supabase SQL 적용과 GitHub Pages 재배포가 완료되어야 새 규칙이 적용됩니다.


## 제시 포인트 비공개 규칙

게임 진행 중에는 상대의 제시 숫자와 정확한 잔여 포인트를 공개하지 않습니다. 남은 포인트 표시등과 라운드 승패/누적 승점은 확인할 수 있습니다. 양쪽의 실제 제시 포인트가 포함된 전체 라운드 로그는 게임 종료 후 공개됩니다. 이 변경을 적용하려면 `index.html`과 `supabase.sql`을 모두 배포하고, Supabase SQL Editor에서 전체 `supabase.sql`을 다시 실행하세요.
